# PS-026 — B2 Evidence Explorer — Proof

## Roadmap alignment

PS-026 returns to the PS-022 master roadmap after the controlled PS-025
blocker-resolution slice. PS-022 roadmap item:

- PS-026 — B2 Evidence Explorer

PS-024 revealed the public passport blocker. PS-025 unlocked the golden public
passport contract locally. PS-026 now makes the verified B2 evidence visible
and judge-friendly as a first-class product surface.

## Product surface chosen

A dedicated frontend route `/b2-evidence` backed by a new
`apps/web/src/B2EvidenceExplorer.tsx` component, plus an inline `variant="section"`
embedding inside `apps/web/src/PublicPassportPage.tsx` (only when the page is
rendering the verified golden demo run), plus CTAs from
`apps/web/src/JudgeCockpitHome.tsx` (both in the "Golden demo run" panel and
in the "Direct CTAs" grid).

This combination was chosen because:

1. It gives judges a clear, deep-linkable B2 Evidence Explorer surface
   (`/b2-evidence`) without requiring them to open the golden passport first.
2. It also surfaces the same evidence inline while a judge is already viewing
   the golden passport, so the durable proof is impossible to miss.
3. It is purely frontend — no new API endpoint, no provider call, no B2 read,
   no broad durable read. The backend PS-025 golden demo unlock continues to
   serve the live passport; PS-026 simply makes its verified evidence visible.

All displayed values come from a single source-of-truth constants module,
`apps/web/src/b2Evidence.ts`, sourced verbatim from the checked-in
`docs/evidence/demo/golden-demo-run.json`. The PS-026 smoke validates every
constant matches the manifest and the PS-021 source evidence exactly.

## API contract

No new API endpoint was added.

PS-026 reuses the existing PS-025 backend contract: `GET /runs/<golden_run_id>/passport`
still resolves the golden demo run from checked-in evidence only, returns the
`golden_demo_unlock` block with the verified archive URI / SHA-256 /

## No-fake-B2 confirmation

PS-026 does not fake any B2 read. The B2 Evidence Explorer renders verified
constants sourced from checked-in evidence files; it does not fetch the B2
object itself, does not build a B2 URI from arbitrary user input, and does
not claim the B2 object was publicly fetched in the browser. The explorer
explicitly states it "references the URI and SHA-256 but does not fetch the
object itself".

## No-provider-call confirmation

## Read-only regression (prior-slice evidence ownership)

### Root cause

The original PS-026 validation flow invoked the PS-025 smoke as a regression
check. The PS-025 smoke rewrites its own evidence JSON
(`docs/evidence/ps-025/public-durable-passport-unlock-smoke.json`) on every run
to record a fresh `checked_at` timestamp. Even though the only field touched
was a timestamp, the PS-026 smoke was leaving a prior-slice evidence file dirty
in the working tree. PS-026 must not modify PS-025 evidence under any
circumstance — regression checks must be read-only from PS-026's working tree
perspective.

### Fix

PS-026 owns only its own evidence output (`docs/evidence/ps-026/`). The
PS-026 smoke now treats every evidence file outside `ps-026/` as immutable:

- Before invoking any regression smoke, the smoke snapshots the exact byte
  content of every prior-slice evidence JSON under `docs/evidence/` (excluding
  `ps-026/`).
- It runs the PS-025 / PS-024 / PS-023 regression smokes under that snapshot.
- It restores the exact bytes afterward, in a `try/finally`, so the working
  tree is byte-identical to its pre-regression state even if a regression
  smoke times out or fails.
- It then runs an explicit assertion, `no_prior_slice_evidence_modified`,
  which independently confirms via `git status` that no evidence file outside
  `docs/evidence/ps-026/` is left modified by the PS-026 smoke run.

The real PS-025 smoke is still executed (so the regression check is faithful
and not a re-implementation), but its evidence write is made transparent and
ephemeral from PS-026's point of view. PS-025 evidence is therefore restored
and clean after the PS-026 smoke completes.

## Limitations

- PS-026 proves the **local contract** only: the frontend constants match the
  checked-in manifest and PS-021 evidence, and the FastAPI TestClient still
  resolves the golden run from a fresh empty store. The public Render
  deployment is **not** verified here; `public_deployment_pending` is true.
- The B2 Evidence Explorer references the archive URI and SHA-256 but does not
  fetch the B2 object itself from the browser. Independent byte verification
  against the recorded SHA-256 is left to the judge.
- No new durable-read scope, no new B2 object path, no new provider call, and
  no new secret surface is introduced.
- The explorer is read-only; it cannot mutate evidence, runs, or archives.
- The read-only regression guarantee applies to the **PS-026 smoke**: it does
  not leave prior-slice evidence dirty. Running the standalone PS-025 smoke
  directly still rewrites its own evidence JSON (that is PS-025's own
  behavior, not PS-026's), so the verification sequence restores it with
  `git checkout --` before re-running the PS-026 smoke.
