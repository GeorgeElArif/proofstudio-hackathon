# PS-027 — Genblaze Pipeline Graph — Proof

## Roadmap alignment

PS-027 continues the PS-022 master roadmap after PS-026 (B2 Evidence Explorer)
made Backblaze B2 evidence visible as a product surface. PS-022 roadmap item:

- PS-027 — Genblaze Pipeline Graph

PS-026 made B2 evidence visible. PS-027 now makes Genblaze orchestration
visible as a first-class product surface so judges can see the full pipeline
without inferring it from code, JSON, smoke scripts, or docs.

## Product surface chosen

A dedicated frontend route `/genblaze-pipeline` backed by a new
`apps/web/src/GenblazePipelineGraph.tsx` component, plus CTAs from
`apps/web/src/JudgeCockpitHome.tsx` (both in the "Golden demo run" panel and
in the "Direct CTAs" grid), plus a backlink from
`apps/web/src/B2EvidenceExplorer.tsx` (page variant only).

This combination was chosen because:

1. It gives judges a clear, deep-linkable Genblaze Pipeline Graph surface
   (`/genblaze-pipeline`) without requiring them to open the golden passport
   or the B2 Evidence Explorer first.
2. It exposes the full pipeline as nodes and edges: Brief → ProviderRouter →
   Genblaze orchestration → Media generation attempt → Asset/manifest capture
   → Backblaze B2 archive → Provenance passport → Durable rehydrate (zero
   provider calls) → Judge review.
3. It is purely frontend — no new API endpoint, no provider call, no B2 read,
   no broad durable read. The backend PS-025 golden demo unlock continues to
   serve the live passport; PS-027 simply makes the verified pipeline
   orchestration visible.

All displayed values come from a single source-of-truth constants module,
`apps/web/src/genblazePipeline.ts`, sourced verbatim from the checked-in
`docs/evidence/demo/golden-demo-run.json` (PS-024 manifest) and the PS-021 /
PS-025 / PS-026 source evidence. The PS-027 smoke validates every constant
matches the manifest and the PS-021 / PS-025 / PS-026 source evidence exactly.

## Graph node list

The graph renders 9 required nodes, each tagged with a truth class so the
verified-vs-inferred-vs-local-contract-vs-pending distinction is visible:

1. Campaign brief — `inferred_explanation`
2. Provider Router — `inferred_explanation`
3. Genblaze orchestration — `inferred_explanation`
4. Media generation attempt — `inferred_explanation`
5. Asset / manifest capture — `inferred_explanation`
6. Backblaze B2 archive — `verified_evidence`
7. Provenance passport — `local_contract_proof`
8. Durable rehydrate — `verified_evidence`
9. Judge review — `inferred_explanation`

Nodes are NOT presented as direct Genblaze SDK primitives. Each node's detail
copy states exactly what it represents and what evidence (if any) backs it.

## Graph edge / story list

The graph renders the required directed edge story:

1. Brief enters pipeline (`brief → router`)
2. Router selects provider path (`router → genblaze`)
3. Genblaze-backed flow records generation/provenance (`genblaze → media`)
4. Asset and manifest are captured (`media → capture`)
5. Asset and manifest are archived to B2 (`capture → b2`)
6. Passport exposes run proof (`b2 → passport`)
7. Rehydrate loads durable archive (`passport → rehydrate`)
8. Rehydrate uses zero provider calls (`rehydrate → rehydrate`, self-loop)
9. Judge reviews evidence (`rehydrate → judge`)

## Genblaze claim boundary

The graph carries an explicit Genblaze claim boundary panel listing allowed
and forbidden claims.

**Allowed claims:**

- Genblaze is used in the ProofStudio pipeline.
- The pipeline records provider/model/provenance and B2 archive evidence.
- This golden run has verified archive and rehydrate proof.

**Forbidden claims (rendered as non-claims):**

- Genblaze does not independently certify the truth of the media.
- The media is not legally authentic.
- The asset is not C2PA-authenticated.
- The archive is not tamper-proof.
- Object Lock is not enabled.
- Public deployment has not been verified (it remains pending).

## No-broad-B2-read confirmation

PS-027 introduces zero broad B2 reads. The PS-027 smoke scans every changed
file for forbidden B2 read patterns (`read_archive_from_b2`, `b2.fetch`,
`b2GetObject`, `list_b2_objects`, `fetchB2Object`) and validates an arbitrary

narrow allowlist (golden demo only) is unchanged.

## No-prior-slice-evidence-mutation confirmation

No historical evidence JSON (PS-019/020/021, PS-024 golden manifest, PS-025
unlock evidence, PS-026 explorer evidence) was modified by PS-027. The PS-027
smoke enforces this in two layers:

1. Before invoking any regression smoke, the PS-027 smoke snapshots the exact
   byte content of every evidence file outside `ps-027/`. It also temporarily
   removes its own evidence output (`docs/evidence/ps-027/...`) so that
   historical regression smokes (PS-026 in particular) do not flag the new
   ps-027 evidence as dirty prior-slice evidence.
2. It runs the PS-026 / PS-025 / PS-024 / PS-023 regression smokes under that
   snapshot, then restores the exact bytes afterward (try/finally), so the
   working tree is byte-identical to its pre-regression state.
3. It then runs an explicit assertion, `no_prior_slice_evidence_modified`,
   which independently confirms via `git status` that no evidence file outside
   `docs/evidence/ps-027/` is left dirty.

## Limitations

- PS-027 proves the **local contract** only: the frontend constants match the
  checked-in manifest and PS-021 / PS-025 / PS-026 evidence, and the FastAPI
  TestClient still resolves the golden run from a fresh empty store. The
  public Render deployment is **not** verified here;
  `public_deployment_pending` is true.
- The Genblaze Pipeline Graph references the archive URI and SHA-256 but does
  not fetch the B2 object itself from the browser. Independent byte
  verification against the recorded SHA-256 is left to the judge.
- The graph shows the pipeline stages as inferred product explanation where
  no per-node evidence is pinned (brief, router, genblaze orchestration,
  media generation attempt, asset/manifest capture, judge review). Only the
  B2 archive node and the durable rehydrate node carry verified evidence;
  the passport node carries local contract proof. This is shown honestly via
  the truth-class pills.
- No new durable-read scope, no new B2 object path, no new provider call, and
  no new secret surface is introduced.
- The graph is read-only; it cannot mutate evidence, runs, or archives.
- The read-only regression guarantee applies to the **PS-027 smoke**: it does
  not leave prior-slice evidence dirty. Running the standalone PS-025 or
  PS-026 smoke directly still rewrites its own evidence JSON (that is the
  prior slice's own behavior, not PS-027's).
